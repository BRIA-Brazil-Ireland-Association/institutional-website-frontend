# Report landing page (BRIA Report 2026)

Lead-capture page for the report _Brazilian Talent in Ireland_. One page per language, so campaign links (UTM) are reported per version:

| Language   | Public URL              | File served                        |
| ---------- | ----------------------- | ---------------------------------- |
| English    | `/en/report-2026`       | `public/report-2026/en/index.html` |
| Portuguese | `/pt-BR/relatorio-2026` | `public/report-2026/pt/index.html` |

The pages are static HTML (no React, no site Navbar or Footer: the form is the only action on the page). `next.config.ts` rewrites the two URLs to the files. Shared images live in `public/report-2026/assets/`.

The HTML is generated by `build-landing.py` in the BRIA report project (`Previews-HTML/06-Landing-Page/`), which writes straight into `public/report-2026/`. Copy changes go through that script, not by hand in the HTML.

## How a lead is saved

```
form (static page)
  └─ POST /api/report-lead            app/api/report-lead/route.ts
       Zod validation, honeypot, never trusts the browser
       └─ POST Apps Script web app     docs/report-landing-page/apps-script/Code.gs
            checks the shared secret
            appends a row to the "Leads" tab of BRIA's Google Sheet
```

When the API answers `201`, the page shows the thank-you message and downloads the report PDF in the browser (`public/report-2026/assets/BRIA-Brazilian-Talent-in-Ireland-2026.pdf`, one English file for both pages), with a link in the message in case the download is blocked. The report is not emailed.

The Apps Script URL and the secret stay on the server (Vercel env vars). The browser only sees `/api/report-lead`, so nobody can write to the Sheet without going through the validation.

Columns in the Sheet: `submitted_at, name, email, organisation, profile, consent, updates, lang, utm_source, utm_medium, utm_campaign, utm_content, utm_term, landing_url, referrer, report_email`. `profile` always holds the English label, also for the Portuguese page. `report_email` stays `not_sent: no report url`, because `REPORT_URL_EN` is left empty (the email code in `Code.gs` is unused).

## Launch event pages

Two more static pages, generated by `build-forms.py` (same folder as `build-landing.py`), save to the same Sheet through the same Apps Script, each in its own tab. They send no email.

| Page                                                      | Public URLs                                                                | API route             | Tab              | Columns (plus the tracking ones)                           |
| --------------------------------------------------------- | -------------------------------------------------------------------------- | --------------------- | ---------------- | ---------------------------------------------------------- |
| RSVP (invited guests)                                     | `/en/report-2026/event`, `/pt-BR/relatorio-2026/evento`                    | `/api/event-rsvp`     | `RSVP`           | `submitted_at, name, email, institution, consent, updates` |
| Interest in attending (open community, no place promised) | `/en/report-2026/event-interest`, `/pt-BR/relatorio-2026/evento-interesse` | `/api/event-interest` | `Event interest` | `submitted_at, name, email, consent, updates`              |

Tracking columns: `lang, utm_source, utm_medium, utm_campaign, utm_content, utm_term, landing_url, referrer`. Both tabs end with `phone`: an optional field on the page (country code select + number). The routes validate it (`phoneFields`, `isValidPhone`, `withPhone` in `libs/sheet-forms.ts`) and send one `phone` value such as `+353 87 123 4567`, or an empty string. The tabs are created with their header row on the first submission; `getSheet_` also adds a missing header cell (such as `phone`) to a tab created before the column existed.

The landing page's thank-you card also shows a link to the event-interest page until `EVENT_INVITE_UNTIL` in `build-landing.py` (30 November 2026, 12:00 in Ireland, the day before the event). The check runs in the visitor's browser, so it disappears on time without a deploy.

### Sponsors and Supporters sections

Both event pages show a Sponsors section under the hero, and the report landing shows a Supporters section right above its footer, each with its own list. They are filled in the browser from `GET /api/event-sponsors?page=event` and `?page=report` (`app/api/event-sponsors/route.ts`). The route posts `{secret, action: "sponsors"}` to the same Apps Script, which reads a separate Google Sheet (tab `Sponsors`: `order, name, logo, website, event, report`, where the two checkbox columns say where each logo shows) and the logos' Drive folder, and returns each ticked row with its logo as a base64 data URI. The route keeps only the rows for the requested page, validates every item with Zod, drops anything that is not a `data:image/...` logo or an `http(s)` link, and is cached on the CDN for 10 minutes (`CDN-Cache-Control`), so the Sheet can change without a deploy. Up to six logos sit in one row; more than six scroll as a marquee (static grid under `prefers-reduced-motion`). If the route fails or the list is empty, the section stays hidden.

Extra script properties: `SPONSORS_SHEET_ID` and `SPONSORS_FOLDER_ID`. `appsscript.json` adds the `spreadsheets` scope (`SpreadsheetApp.openById` does not accept `spreadsheets.readonly`; the script only reads the sponsors Sheet) and the read-only `drive.readonly` scope; run `testSponsors` once to grant them, then publish a new version. No new Vercel env vars.

## Setup (once)

1. **Sheet.** With BRIA's Google account, create a Google Sheet (for example _BRIA Report 2026 · Leads_). Share it only with the people who need the leads: the privacy policy says only authorised BRIA team members can access it.
2. **Script.** In the Sheet: Extensions > Apps Script. Replace `Code.gs` with `apps-script/Code.gs`. In Project settings, tick _Show "appsscript.json"_ and replace it with `apps-script/appsscript.json`.
3. **Script properties** (Project settings > Script properties):

   | Property        | Value                                                          |
   | --------------- | -------------------------------------------------------------- |
   | `SHARED_SECRET` | a long random string, for example from `openssl rand -hex 32`  |
   | `REPORT_URL_EN` | leave empty: the report is downloaded on the page, not emailed |
   | `REPORT_URL_PT` | leave empty                                                    |
   | `REPLY_TO`      | optional, the address replies and unsubscribe requests go to   |
   | `TEST_EMAIL`    | optional, used only by `testDoPost`                            |

4. **Test inside Apps Script.** Run `testDoPost` once and accept the permissions (Sheets of this file, send email as you). A row appears in the `Leads` tab.
5. **Deploy.** Deploy > New deployment > Web app. Execute as: _Me_. Who has access: _Anyone_. Copy the URL ending in `/exec`.
6. **Vercel.** Add the env vars to the project (Production and Preview), then redeploy:

   ```
   REPORT_LEADS_SCRIPT_URL=<the /exec URL>
   REPORT_LEADS_SECRET=<the same SHARED_SECRET>
   ```

After editing `Code.gs`, publish with Deploy > Manage deployments > Edit > New version. The `/exec` URL stays the same.

## Test the whole flow

```bash
curl -i -X POST http://localhost:3002/api/report-lead \
  -H 'Content-Type: application/json' \
  -d '{"name":"Test Lead","email":"test@example.com","profile":"Other","consent":true,"updates":false,"lang":"en","utm_source":"test"}'
```

`201` means the row was saved. `400` is a validation error, `500` means the env vars are missing, `502` means the Apps Script call failed (check Executions in Apps Script).

## Cookies and analytics

Google Analytics 4 (`G-MZVWM336V1`) runs on the whole site, these static pages included, only after the visitor accepts the cookie banner. One script does it everywhere: `public/cookie-consent.js`, loaded by `app/[locale]/layout.tsx` and by a `<script src="/cookie-consent.js" defer>` tag that `build-landing.py` and `build-forms.py` add to each static page.

- The banner shows until the visitor chooses. "Decline" is as prominent as "Accept", as the Irish DPC requires.
- The choice is kept in `localStorage` (`bria_consent` = `granted` or `denied`) and is shared by the site and these pages.
- Any link ending in `#cookie-settings` reopens the banner (site footer, Information column, and the footer of each static page). Declining after accepting deletes the `_ga` cookies.
- Ads signals stay off (`ad_storage`, `ad_user_data` and `ad_personalization` denied). Vercel Analytics keeps running without cookies.
- To change the measurement ID, edit `GA_ID` at the top of `public/cookie-consent.js`.
